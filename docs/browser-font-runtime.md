# 中文竖排字体运行约定

## 原因与修复

在 Playwright 1.60.0 Noble Runner 的当前中文字体回退环境中，Chromium 使用
WenQuanYi Zen Hei 渲染 `writing-mode: vertical-rl` 时，中文字符的竖向推进距离为零。
四字标签只剩字间距（约 10.25 px），字形互相覆盖；这与页面网络、Excel 步骤、截图等待无关。

Runner 构建安装 Ubuntu Noble 的固定包 `fonts-noto-cjk=1:20230817+repack1-3`，
移除存在异常的 `fonts-wqy-zenhei` 后刷新系统字体缓存，避免复杂回退链再次选中该字体。
只安装 Noto 而保留文泉驿的第一版候选在真实 043 中仍失败，不能作为修复完成的依据。
中文默认回退使用 Noto Sans CJK SC；同一离线页面标签高度恢复到约 70.25 px。
不注入页面 CSS、不覆盖产品字体声明、不更换标准图、不放宽模型或像素判定。

## 两层门禁

- 正式包工作流先对固定 TOP Dockerfile 应用字体构建约定，再以非 root 的 `pwuser`
  执行 `utils/browser_font_health.py`。构建约定不匹配或实际 Chromium 排版异常时构建失败。
- 每个 pytest 浏览器会话的首个视觉用例运行同一自检；后续视觉用例复用成功结果。
  自检在独立空白上下文中运行，不访问业务网站、不使用登录状态、不调用模型，不改变被测页面。
- 自检测量八个汉字在横排与竖排中的实际字符位置，不以“字体文件存在”或模型给出通过作为依据。
- 自检覆盖中文、英文和未声明页面语言，以及通用、Arial、页面常用字体栈和旧文泉驿回退链。
- 新增用例只要采用已有 `vision_*` 断言或 `vision_compare_step`，自动执行此检查，无需修改 Excel。
- 失败标识 `BROWSER_CJK_FONT_METRICS_INVALID` 表示应修复 Runner 环境，不能通过更新标准图消除。

## 发布与验证

字体是镜像的一部分，必须发布新的完整 Web Runner 包；仅同步 Excel 基线不会安装字体。
禁止在已发布镜像对应的在线 Worker 中临时安装字体后仍宣称它是原签名镜像。
本地候选镜像只用于验证；正式启用仍需新版本签名、供应链核验和 TOP 回归门禁。
旧版本与原始标准图保留用于回退和对照。
